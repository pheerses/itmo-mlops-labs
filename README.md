## Проверка поставки

GitHub Actions собирает индекс, проверяет API, MRR и Recall@3, проверяет отказ при обратном ранжировании, публикует образ в GHCR и испытывает один digest в staging и production отдельного кластера kind. В артефактах quality и rehearsal доступны отчёты, ответы сервисов, фактические образы и история Helm. Поиск по контрольному запросу должен возвращать doc-rollback первым.

Для учебного кластера используются ручные запуски workflow на main с target=staging и затем target=production и тем же digest. Перед запуском задаются KUBE_NAMESPACE и secret KUBE_CONFIG_B64 для выданного доступа. Образ должен быть доступен для скачивания из namespace. Production проверяет digest работающего staging. Для production workflow требуется ручной выбор окружения и digest; в настройках GitHub Environment можно дополнительно назначить рецензента.

Readiness показывает, что процесс загрузил индекс и обслуживает запросы. Перевёрнутое ранжирование сохраняет эти свойства, но меняет первый результат. После отрицательного semantic smoke pipeline откатывает production к сохранённой ревизии и проверяет выдачу повторно.
